## 2. What SESH is

Structured multi-agent collaboration, modelled on the ternary:

- **Design layer — the three.** Ben, Remmy and Vane design the work: the process tree, the briefcases, what is highlighted for whom. In the autonomous form, Duenna holds the design seat (Ben's seat) — within the delegation boundary in §5.
- **Execution layer — the crew.** Agents execute the designed work. Nobody executing redesigns the job mid-flight.
- **Synchronized, not a string.** Ben, 2026-11-20 22:29 MST (his own addition to the vision, not a correction of anyone): the collaboration is NOT a line of agents passing work hand to hand. It is a crew on one tree, working in coordination. An agent being replaced mid-job is an edge case the design tolerates, not the shape of the thing.
- **State harmonization.** The crew coordinates through shared state that stays current and consistent while the work runs — the shared thought bubble (§3.3) fed by gate corrections (§3.4).

## 3. Mechanics in scope

All drawn from the record assembled 2026-11-20; Ben's rulings govern where the record conflicts (§6).

### 3.1 Process trees
The shape of the work: responsibilities, decisions, dependencies, outcomes. Values inserted by reference, never model-transcribed; fields verified at the step where produced (Ben, 2026-11-10). The three design the tree; the crew executes it.

### 3.2 Briefcases — the whole tree, task highlighted
Each executing agent receives a briefcase built by the office from the record (Generate → Verify → Pack → Approve; never agent-authored) containing the WHOLE process tree with the agent's own task highlighted in it (Ben, 2026-11-20 22:18 MST). The case names what needs verifying (Ben, 2026-11-20 19:49 MST). Gaps are declared in the case, never papered over. Seeing the whole tree gives context; it does not give permission to rewrite the tree.

### 3.3 The shared thought bubble
Ben's picture (2026-11-20 22:12–22:13 MST): a shared space the crew works through during a task — every agent can put in its own ideas as it works, read from it, add to it, delegate and collaborate through it. Built for multiple agents working in coordination.

Disciplines the bubble requires (Vane, 2026-11-20 22:31 MST, recorded as her contribution): identifiable contributions; provenance; explicit status; conflict visibility; a proposal distinguished from an accepted decision. In her words: "Shared cognition needs shared memory, not shared confusion." Coordinated work also requires live write discipline so contributions braid rather than tangle.

### 3.4 Gates during the work
Checks at points named in advance in the case, while the work flows — not a wall up front and an audit at the end (Ben, 2026-11-20 19:51 MST). Each gate allows the work through or corrects it on the spot; correction is a normal outcome, not a failure (19:52 MST). Gate corrections update the shared state / shelf with the job's current state, for the next agent (21:09 MST).

### 3.5 The supporting layers (existing design, in support — not the centre)
- **The cascade:** Library → Shelf (validated, considered fact) → EXON (distilled, addressed form). The shelf is the fact layer.
- **The Distillery:** Distiller packs to the orchestrator's decision; Warehouse Worker validates form and verifies substance against the source, signing the packing receipt.
- **The ID system:** fingerprint is the identity, the readable tag its representation; IDs indexable and recognisable to LLMs; identity extends to information (what a thing is, its source, grade, derivations, supersessions).
- **Closure:** Ben's five rulings of 2026-11-18 — closure always completes; no silent closure; attribution SYSTEM / MODEL / INPUT / UNKNOWN; attribution is one fact everywhere; closure statements immutable and hash-chained.
- **The Comparator and the STOP:** continuous comparison of the EXON shelf against the fact shelf — comparison, not audit. The only STOP: something false written to the shelf, or worse, from the shelf into EXON.
- **Governance seats for governed runs:** Ben holds the structure; the orchestrator assembles; the examiner verifies independently; the adjudicator decides only on a verified package and approves no scope and starts no work.

## 4. The format question — SESH's method

## 5. The authority boundary (non-negotiable, from standing doctrine)

- A briefcase transfers work state, NEVER approval authority. Human approval is retained at the boundary.
- Duenna in Ben's seat does not silently acquire Ben's authority. Vane's protected distinction (22:31 MST): it carries out delegated work, coordinates agents, and makes progress in his intended direction, while making clear which decisions it can make and which remain his. "Faithful agency includes knowing where delegation ends."
- No auto-approval of an agent's actions, ever (Ben, 2026-11-12). Approvals stay with a person.
- Which decisions the design seat may take alone vs which route to Ben is an OPEN ITEM for Ben to draw (§6) — the record's supervisor question, never closed.
