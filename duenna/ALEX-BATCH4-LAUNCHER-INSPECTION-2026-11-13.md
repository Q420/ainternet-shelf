Disposition: NOT CLEARED — source correction required before Batch 4 can begin. I compared the full 708-line source against the Batch 0 interface freeze and Rev 26 §3.5. The following are source-level findings, not runtime test results.

Blocking findings:
1. HIGH — Run-ID parser is incorrectly offset (launcher.c:274–289). dash2 − 9 points to the delimiter before the date, not the first date digit; subsequent checks treat that delimiter as a digit and inspect the wrong character for the preceding separator. Valid identifiers are rejected; short malformed inputs can also cause pointer arithmetic before the beginning of the string. Correct the parser and test valid identifiers, boundary lengths, malformed separators, and impossible calendar dates.
2. HIGH — Child's first instruction violates the frozen sequence (launcher.c:538–542). The forked child closes gate[1] and CHANNEL_FD before entering child_main(), where its first getppid() check occurs. The freeze requires the inherited-parent identity check as the child's first act (pre-first-instruction parent-death case). The order must be corrected, not merely documented.
3. HIGH — Exhaustive descriptor closure is not fail-closed (launcher.c:446–450). Every close_range() return value is ignored; a failed call lets the child continue towards the gate and potentially exec with inherited descriptors still open. Every required close must be confirmed; a failed or incomplete close must terminate the child without executing the harness.
4. HIGH — Unavailable file-capability inspection is treated as success (launcher.c:356–357). ENOTSUP is treated identically to ENODATA; the former means the inspection is unsupported. The freeze requires unavailable or incomplete capability verification to fail closed. ENOTSUP must not establish an empty capability set.
5. HIGH — Class-T ABORT recognition lacks packet validation (launcher.c:668–670). The launcher triggers the class-T STATUS action whenever byte 0 is MSG_ABORT and byte 2 is the class-T reason, without validating flags, exact length, or detail framing. A malformed packet can trigger the class-T lifecycle action. Validate the complete incoming ABORT structure before dispatching on its reason.

Additional protocol findings:
6. MEDIUM — Receive errors are conflated with EOF (launcher.c:659–666). chan_recv() distinguishes EOF (−1), malformed (−2) and receive error (−3); the Stage 6 loop treats all negative values as EOF. Preserve the distinction; malformed input and receive errors must follow their specified failure behaviour.
7. MEDIUM — Unexpected ancillary data is not comprehensively rejected. chan_recv() only recognises SCM_RIGHTS; other control messages can pass without setting anc, and multiple descriptor-control messages deserve explicit handling. The contract says unexpected ancillary data is a protocol violation. Ensure all unexpected control data is rejected and every received descriptor is closed.
