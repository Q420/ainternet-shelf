**Part 2 — no silent exit.** New core: handles.js (below). The letterbox's handoff is now acknowledged: commit builds an awaiting-ack entry and the seen/handed-off marking is applied ONLY on an accepted or duplicate-terminal answer (confirmAck). The background answers every pb-detection in one of four classes — accepted / duplicate (terminal, with a re-sighting log line; the pre-existing silent duplicate return now logs and carries answerClass) / rejected (unregistered tab) / unanswered (no answer arrives). Rejected and unanswered retry on a bounded schedule (2 s, 5 s, 12 s), then the failure is reported through the drop channel and the letter is NOT marked — it can pend again on a later scan. Drop reports (pb-capture-drop) ride the same discipline from content.js with their own bounded retries; a final drop-report failure has nowhere above the content layer to report to and leaves a console trace — named here as the build's one accepted reporting limit. The letterbox pending-cap eviction (silent since v0.6.3) now reports through the drop channel. Content.js builds ONE envelope per letter, reused across retries, so a retry is the same message_id — background dedup can tell a retry from a new letter. While a tab is not the live detector, the handoff answers "rejected — bridge off": bounded retries, a drop report, and re-pending on a later scan replace the old silent absorption. Growth of a letter whose handoff is still unconfirmed replaces the awaiting payload (lineage = the awaiting body's fingerprint), so exactly one chain of attempts exists per letter. Intake also consults the handle store BEFORE the fpToId check (errata G2): an exact re-sighting of a completed letter answers duplicate-terminal from the handle, logged as RE-SIGHTING AFTER CLOSE.

**Part 3 — the tombstone.** retirePair now leaves a retained handle (via pbLeaveHandle) before each forget, for the pair's call and reply and for a retired pending reply.
