## Scope

1. **Seal attempts (§7), with the complete check set (B1).** Attempted after **every accepted commit**, and once more at run close if the last accepted commit was not already followed by an attempt; unconditional — an open structural tension never prevents, delays, or conditions an attempt. The checks divide by their object:
   - **Against the live derived state:** S1 dependency integrity, S2 version monotonicity, S3 pattern acyclicity. (S4 declared scope remains enforced where Rev 9 places it — at schema and targeting validation, not as a seal check.)
   - **Against the event history:** schema conformance of the recorded events and hash-chain continuity to the sealed position. These are not substitutes for S1–S3.
   Each attempt is recorded as a `SEAL_ATTEMPTED` event with an explicit outcome. On `pass`, a seal is issued for that event position recording: the position; the contributions included since the last seal; the checks performed; and the outstanding semantic questions, each marked examined-by-whom or *unexamined* — the record stating in terms that a seal never implies semantic clearance. On `fail`, no seal is issued and the event records which checks failed and the affected records.
2. **The transaction boundary (B3).** One atomic group per accepted contribution, deterministic order: (i) the accepted contribution's events; (ii) contribution-triggered tension and facet transitions; (iii) `SEAL_ATTEMPTED`; (iv) any structural `TENSION_RAISED` / `TENSION_STATUS` events caused by that attempt. The whole group commits or rolls back together; no observer sees a partially committed group. The checker evaluates the **staged** post-contribution state and candidate event batch **before** commit, receiving them as explicit inputs alongside its read-only access to the committed history. A passing seal is anchored to the `SEAL_ATTEMPTED` event position and covers the structural state **at that position only**, not later events — including a resolving `TENSION_STATUS` that follows it inside the same group.
3. **The structural lifecycle, genuinely (§7, B6).** Identity = (check name, affected record set), the set canonically ordered for comparison. A failing check raises the tension (`TENSION_RAISED`, origin `checker`, status `open`) as part of the same attempt processing — unless one with that identity already stands open, in which case the attempt's findings attach to the standing tension and no duplicate is raised; a different affected set is a different identity. **Resolution re-runs the same check against the original tension's affected record set**: a tension resolves (`open → resolved`, `TENSION_STATUS` whose evidence is the passing attempt's event id) only when that check establishes that the particular inconsistency the tension represents no longer exists — never merely because a later attempt failed differently or another check passed. This delivers the genuine TV-13 resolution path deferred from Stage 3.
4. **The independent checker (§7, B2).** Its own implementation, executed as a separate process, importing **no** engine or harness logic. It may share the canonical-JSON and hash primitives (they define the record format). It independently implements: event folding and state derivation; the S1, S2 and S3 checks; seal eligibility and outcome; structural-tension identity, deduplication and resolution. It takes **two distinct inputs**: (a) the event history, read-only, from which it independently derives the expected state; and (b) a read-only **snapshot of the actual live derived state** at the attempt boundary. It runs the structural checks against the live snapshot and compares the snapshot with its replay-derived state. The snapshot is input evidence, not authority. A seal the checker does not reproduce is not a seal, and the discrepancy is recorded.
5. **The checker-validation pack (B4).** **Authored by Vane** from the specification text, not from either implementation; examined and challenged by Remmy. The pack is visibly identified as examiner-authored, versioned, and hash-pinned; Annex E remains the contract's stated vector set, and the pack is additional pinned material, not a renaming of it. Before any run opens, **both** implementations are tested against the same pinned pack; a disagreement means the run does not open. The run record identifies the exact pack and its hash.
6. **Vectors in scope:** TV-1, TV-6, TV-8, and TV-13's genuine resolution half — each a named executable test with observable evidence. **TV-1's evidence (B5)** must show: valid replay before and after the injection; the exact live-state mutation; the checker detecting the resulting S1 inconsistency; the failed attempt and the raised structural tension; a genuine correcting contribution; an unconditional subsequent attempt; the passing result and the resolution evidence. The ordinary contribution that triggers the first attempt is **independent of the missing region**, so the contribution itself is not invalid. TV-6 exercises B6 both ways: repeated failures with the same identity attach to the standing tension (no duplicate), and a different affected set is a different tension.
7. **Carried hardening obligation (from Vane's Stage 3 acceptance).** Malformed event payloads convert to a controlled `ReplayHalt` at the offending sequence, never a native `TypeError` — including hash-valid events whose tension `type`, or transition `from`/`to` values, are unhashable. Negative replay tests in the Stage 3 corrections style, each verifying the chain itself is valid, so the test proves protocol validation rather than hash rejection.
8. **Starvation reporting (B8).** A **named derived-report module with its own tests** — a deterministic read over the event history, never authoritative state. Its measures are defined unambiguously in the build notes before use: rejections by outcome, consecutive rejections, wakes between successful commits, changed-read diff sizes, and progression. It reports **every** agent, including agents with no successful commits; no-progress is reported as measured values, never omitted or left undefined.
9. **Run close and the anchor, named honestly (B7).** `RUN_CLOSED` records the final state hash and the chain head. The shelved closing record and its Git commit SHA are recorded beside them, with the relationship stated: the shelf provides a **content-addressed archival anchor outside the event database** — it establishes that this exact record was published at that commit; it is **not** an independently trusted external anchor, because the commit SHA is not itself preserved outside the repository's control. The evidence says precisely that, no more.
10. **The closing exercise, honestly bounded.** After the above: one full mechanical lifecycle run exercising the whole slice end to end, with the complete Annex E TV-1..TV-20 evidence pack executed and presented together — the package for the later integrated examination. **The exercise is an evidence package, not a success claim**: a run may legitimately end with unresolved semantic work or a failed structural condition, and the exercise preserves and reports whatever outcomes occur; it never manufactures a pass by selecting a favourable lifecycle. Still mechanical/driver-run; **no live agents**.

## Not in scope

Live agents (unauthorised); the observer's next round (follows the mechanical lifecycle); anything beyond the commissioned slice.
