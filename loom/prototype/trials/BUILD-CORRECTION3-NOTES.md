## The defect (as examined)

`ledger/gt_release.py` defaulted `GT_FILE` to `gt-store/layer4-packet.txt` — the round-1 Annex A/C packet — when `GT_RELEASE_FILE` was unset. The round-2 runner avoided the wrong selection only by setting the variable before import, so a release invocation without that setting silently selected the wrong packet.

## The correction — chosen shape (b): explicit selection, absence fails closed

Of the two shapes the dispatch allowed, this round implements **shape (b)**: packet selection is explicit and its absence fails closed. (Shape (a), defaulting to the Annex D packet, was not chosen: a default is still a silent selection, and the defect being corrected is precisely a silent selection.)

**Declared code change — `ledger/gt_release.py` only** (plus its regenerated bytecode):

1. **No default.** `GT_FILE = os.environ.get("GT_RELEASE_FILE")` and `GT_FILE_EXPLICIT = "GT_RELEASE_FILE" in os.environ`. The former `layer4-packet.txt` default is gone.
2. **Step 0 of `release()` — packet-selection gate.** If the selection is absent or empty, release returns `{released: False, stage: "packet-selection"}` before the sequence is consulted and before any material can be read.
3. **Step 2.5 — packet binding.** After the (unchanged, D7-B) scoring-order/manifest verification and SCORING_FROZEN anchor validation, and before the access record is appended, the gate:
   - reads the expected packet hash from the sequence's most recent `GROUND_TRUTH_SEALED` event (`sealed_packet_binding()`) — the full value recorded by the sealing act, never hardcoded in the module; a missing or malformed binding refuses at stage `packet-binding`;
   - hashes the selected file as the `loomgt` identity (`selected_packet_sha256()`, `runuser -u loomgt -- sha256sum`) — the same identity that later reads the material, and the only one that can read the sealed store; a file that cannot be hashed refuses at stage `packet-binding`;
   - requires exact equality; a mismatch refuses at stage `packet-binding` with both hashes and the sealing event's seq recorded in the result.
4. The successful access record and result now also carry `packet_sha256`, `packet_binding_event_seq`, and `selected_packet_sha256_verified`.

No other behaviour changed. The D7-B order/binding logic, the anchor structural validation, and the fail-closed anchoring behaviour are byte-for-byte the round-2 code paths; only the additions above and the docstring were edited.
