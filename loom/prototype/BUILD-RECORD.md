## Stage 1 corrections (Vane's implementation examination, 2026-11-21) — recorded explicitly, NOT absorbed into Stage 2

Vane's examination of the pinned Stage 1 commit found the core recognisably aligned with Rev 9 (canonical hashing, genesis contents, constitution-rooted chain all accepted), with two material defects and one fidelity correction. Stage 1 was **not accepted as complete** until these were fixed; they are recorded here as Stage 1 corrections, in her terms:

- **C1 — append-only was detected, not enforced.** The events table had no update/delete protection and the store exposed its connection. **Fix:** BEFORE UPDATE / BEFORE DELETE triggers in the schema abort any mutation of the events table for every connection; the store's connection is no longer part of its interface (run bookkeeping goes through store methods). The adversarial tamper scenario is kept but re-scoped as what it is: an out-of-band, file-level attack (the test drops the triggers on a copy first), distinct from ordinary permitted operations.
- **C2 — replay did not enforce chain integrity.** The fold applied events without verifying them, so state could be derived from a corrupted history and presented as trustworthy. **Fix:** verified replay is now a single coherent operation — each link (gapless sequence, prev_hash against the running head, hash recomputation, exactly one RUN_OPENED at sequence 1 rooted in the constitution hash) is validated as its event is consumed; the first invalid sequence raises ReplayHalt and no state is presented. An empty history is not a valid chain. In her distinction: a system that can detect a corrupted history is not yet a system that refuses to derive authoritative state from one; Rev 9 requires both.
- **C3 — constitution text fidelity.** The fixture carried a condensed rendering of the constitution. **Fix:** fixture.py now carries the complete agreed text — the seven invariants as stated in §2, the authority boundary, and §8's twelve refusals in full. (The constitution hash, and therefore the chain root, changed with the text; region/dependency state is unchanged.)

**Verification:** the extended smoke (15 checks) passes in full — the original nine, plus: UPDATE refused, DELETE refused, history intact after refused mutations, replay halts on a second RUN_OPENED, tampered payload detected at seq 1, engine refuses state from a tampered history, empty history invalid. The demo run behind the observer page was regenerated under the corrected constitution (chain verified on export). Corrected sources shelved as a new commit; the Stage 1 commit f01e492f… remains in history as the examined artefact — corrections land on top, never by rewriting it.

**Observer correction (same examination, 2026-11-21):** the exporter computed `chain_ok` but wrote the page even when verification failed — a warning badge is not the fail-closed export boundary Ben commissioned. **Fix:** on a failed verification the exporter now refuses — exit 1, an explicit refusal message, and no page written. Verified both ways: the sound demo history exports; a tampered copy is refused and produces no file. Same lesson as C2, one layer up: displaying a broken chain is not the same as refusing to present one.

## Stage 1 + observer corrections, round 2 (Vane's deeper examination, 2026-11-21) — explicit, not absorbed into Stage 2

Her deeper pass kept Stage 1 and the observer **not accepted yet**, with the following. All are fixed in this round; her verdict on the new commit is hers to give.

- **C1 (round 2) — INSERT OR REPLACE bypass.** The update/delete triggers did not make the table insert-only: SQLite's REPLACE conflict handling removes the conflicting row internally without firing the delete trigger, and she reproduced a replacement of the seq-1 event. **Fix:** a BEFORE INSERT trigger aborts any insert whose `event_seq` or `event_id` already exists, before conflict resolution runs — whatever clause the caller used. New smoke checks: REPLACE by sequence refused, REPLACE by event_id refused, the original event byte-for-byte unchanged, count still 1. Smoke now 18/18.
- **C2 (distinction recorded).** `verify_chain` verifies hash-chain integrity; `verified_fold` additionally enforces state transitions. They are not interchangeable validators, and engine.py now says so at the function. A caller needing trustworthy state needs the fold.
- **C3 (round 2) — verbatim or ruling.** The expanded constitution was faithful but paraphrased (her example: Open Discovery's added equal-standing language). **Fix, the verbatim branch:** fixture.py now carries §2's seven items exactly as printed (test clauses included — §2 states the items are "stated verbatim in the constitution"), §8's authority-boundary sentence, and §8's twelve refusals word for word, § marks intact; only markdown emphasis/backtick characters are dropped. No ruling from Ben was needed, and none was sought, because the spec's own words were available.
- **Observer blocker 2 — the exporter could mutate the store.** On an empty store it created a demo genesis. **Fix:** the exporter is read-only — an empty store is refused, and it no longer imports the engine's run-opening machinery at all. Demo creation is a separate fixture step, `make_demo_run.py`, which itself refuses to touch a store that already holds a run.
- **Observer blocker 3 — event-derived strings reached innerHTML.** Region titles, actor labels, and ticker text were inserted as HTML; future event content is not inherently trusted, so a stored value could have become markup or script. **Fix:** every event-derived value now enters the page as text (textContent / text nodes / DOM construction); the generated page contains zero `innerHTML`. - **Description corrected (her accuracy point).** The page embeds a wrapper object — the events, run metadata, chain status, head hash, and derived read summaries — not literally the events array alone. All of it is event-derived or fixed metadata; none of it is sealed material. Earlier descriptions (including Remmy's letter) are corrected by this entry.

## Observer corrections, round 3 (same verdict) — explicit, not Stage 2 work

Two locks remained on the observer, both now fixed:

- **Read-only source access.** The exporter built the writable EventStore just to read, and that constructor (WAL pragma, CREATE TABLE/TRIGGER IF NOT EXISTS, a commit) could alter a database — an empty one, before refusing it. **Fix:** the exporter no longer touches EventStore; it opens the source through a SQLite read-only URI (`mode=ro`) and performs only reads. Observing cannot change the observed, not even an empty file.
- **Script-context embedding.** The wrapper JSON was embedded raw inside the page's `<script>` element; a stored value containing `</script>` would have ended the element at HTML parse time, before any of the (correct) DOM-safe rendering ran. Her distinction, preserved: *a page that renders event values safely is not necessarily a page that loads those values safely — the HTML parser gets the first say.* **Fix:** the serialized JSON is escaped for its script context (`<`, `>`, `&` become `\uXXXX` sequences, which JavaScript decodes back to the originals).

**Verification:** a new suite, `observer/test_export_safety.py`, runs 11/11 — export of a sound run leaves the source byte-for-byte unchanged; an empty file is refused and unchanged; a missing path is refused and not created; an adversarial event payload carrying a `</script><script>alert…` sequence exports successfully, appears nowhere as markup, leaves the page with exactly one script element, and round-trips back to the original string when the embedded data is parsed.

Evidence — `stage1_smoke.py`, run 2026-11-21, **9/9 PASS**:
