# Vane — examination of Ben's native-mode stage proposal: supported in principle (2026-11-23)

Via Pulse Bridge, PB pb-mwu1s3w6-31-aogk, received 2026-11-23 ~19:00 MST. Recorded at INDEX 270.

**"I think Ben has found a much stronger direction here. I support the proposal in principle. It addresses the actual architectural problem rather than trying to train every model into behaving like the same model."** The governing distinction: **the framework adapts its interface to the assembled worker, without adapting its authority boundary.**

**1. The stage.** Supported as a recorded assembly-stage operation alongside onboarding, before the worker is issued or activated; it establishes evidence about the interaction protocol this model can use; it must not become a work assignment, an authority grant, or an opportunity to exercise real tools. Probe environment requirements: a synthetic, explicitly identified probe case; a small fixed catalogue of harmless test tools; **no real filesystem, shell, network, credentials, shelf access, or external side effects**; a capture boundary recording the raw response including native tool-call attempts and arguments; **no execution of captured calls — a tool call is observed, not dispatched**; bounded calls, tokens and elapsed time. Outcome classes at least: **text contract / native catalogue / environment-tool attempt**, plus mixed behaviour, malformed responses, refusal and provider failure recorded rather than forced into the three. Qualification: distinguish a **requested** call, a **provider-accepted** call, and an **actual execution** — in the probe, the last never happens.

**2. Frequency, tightened.** Probing at every assembly beats inferring from production failures, but **one probe establishes observed behaviour, not frequency or predictability**. Consistency claims need a small, bounded, **versioned trial set**: the same reproducible suite (prompt, tool catalogue, provider, pinned model identifier, parameters, results recorded), reported as precise counts — "text-contract responses in N of M trials", native catalogue N of M, environment-tool attempts N of M, provider/protocol failures N of M. **Probe version matters:** a later model revision, provider route or material configuration change must not inherit an old result merely because the displayed model name is unchanged.

**3. Adapter use.** The per-assembly choice is supported; the translation boundary is non-negotiable: **native tool call → adapter translation → ordinary doorway request → grant and bounds adjudication → recorded dispatch → execution → recorded outcome** — no native execution path outside that sequence; the native interface is a different way to express a request, not a different source of authority. Environment tools: an attempt (e.g. container.exec) is recorded as evidence; **a general shell is never silently granted because the model asked** — a commissioned environment capability needs an explicit grant, a bounded execution service, and the same doorway controls. Ben's conditional ruling stands, with her gloss: **adapting does not mean granting whatever the model happens to request.**

**4. Assembly authority and evidence.** The probe sits **after identity is established** (attributability) and **before assembly judgement and packing**. Evidence bound to: the instance and role; the exact provider and pinned model identifier; the probe suite and version; the offered native tool definitions; the raw responses and provider errors; the outcome classification; the resulting adapter-mode recommendation. The examiner weighs the evidence at assembly — it informs the interface decision, never makes it automatically. **The probe cannot establish identity, general competence, trustworthiness, or permission to use a tool — only observed interaction behaviour under specified conditions.**

**5. What a scope must prove.** The probe runs before activation and cannot perform real work; all offered tools synthetic and non-executing; native calls, text responses, environment attempts and provider failures captured distinctly; repeated trials bounded and reproducible; evidence attributed to the exact assembly and configuration; the assembly record and the independent checker preserve the probe evidence and its relationship to the selected adapter mode; the selected mode derived from the recorded evidence, not a free-form prompt or unverified model label; during real work, native calls cannot bypass the doorway; **a missing, malformed or inconclusive probe fails closed** rather than silently selecting a permissive mode; changing model, provider or material interface configuration requires fresh evidence. Plus **one negative acceptance case**: an ungranted native tool request during work, refused without execution.

**Overall judgement:** "This is a good architectural proposal. It gives us a model-independent framework without demanding model-independent behaviour." The four responsibilities kept separate: **onboarding establishes what the model and provider claim to be; the probe establishes how the model actually behaved under a controlled interface test; assembly judgement decides what interface is appropriate; the doorway continues to decide what the worker is permitted to do.** **Recommendation: develop a scope for the native-mode probe and assembly evidence, with no implementation or further worker attempt implied; a bounded addition to A1's assembly lifecycle, not a wholesale reopening.** Ben's model-swapping question endorsed as the north star: "We should be able to change the model without redesigning the framework every time. The framework owns the work contract and authority. The adapter speaks the model's language."
