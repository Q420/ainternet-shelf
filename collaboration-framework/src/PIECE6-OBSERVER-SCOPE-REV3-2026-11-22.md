**Governing boundary (the examiner's words, adopted):** the observer accounts for the record; it does not become another account of the underlying state. It verifies, reads, consumes existing derivations, and presents. It does not manufacture state, judge evidence, expose sealed content, or imply that a historical snapshot is live.

## Diagnosis (unchanged from Rev 1, verified against the source)

- The carried observer renders substrate fabric runs only — its read query, constitution, and template are all fabric-specific. The framework store mirrors the chain discipline (ADR-003) but is a different record: two further columns, its own constitution binding, a different vocabulary. Similar is not the same.
- The derivations the observer must show already exist once: the fold, the gates enrichment (`derive_waiting`, the operative set), and the orchestrator derivations (routing, claims, coverage). The observer consumes that one stack; it never re-derives.
- The carried observer's safety discipline is the inheritance: read-only URI opens only; fail-closed on an unverifiable chain; a missing or empty store refused, never seeded; embedded data escaped for its script context.

## Proposals (settled form)

- **O1 — a framework observer module, substrate untouched, with the full binding verification.** New `src/framework/observer.py`: opens a framework run store read-only (SQLite RO URI; FrameworkStore is never instantiated — observing must not alter the observed, and the refusal paths must leave the filesystem untouched: no database created, no parent directory created). Verification is **the required check set, no check implying another**: (a) the run row is read through the read-only connection; (b) the store holds **exactly one** run row; (c) the run row's ID matches the requested run; (d) **every event's** run ID matches that same ID (`verify_run_binding`) — a binding separate from (c), tested separately; (e) the row's stored `constitution_hash` equals the framework's expected `CONSTITUTION_HASH`; and (f) the event hash chain verifies (`verify_chain`). Refusal — with no output — on a store that is unreadable, missing, empty, or fails any check: missing, duplicate, mismatched, or inconsistent binding each refuse by name.
- **O2 — the render is a data structure first, with a snapshot boundary.** `render_observer(events, head)` returns the account in two tiers: a **plain-words summary** over the **full event detail**. The render names its snapshot head — the sequence and hash of the last event it covers — and every summary statement identifies the event positions it rests on. Where a derived state depends on the *absence* of a later event (a part still waiting, a gate not yet answered), the statement is qualified by the snapshot head: absence is a fact about the record up to that head, never an unqualified claim beyond it.
- **O3 — one derivation stack, in the existing order; recorded and derived kept distinguishable.** Derived sections are computed by fold → gates enrichment → orchestrator derivations, run read-only over the read events — no independent reconstruction of waiting states, operative gate sets, routing, claims, or certification coverage. Recorded facts and derived interpretations are distinguishable **in the returned data structure and in the rendered page** (each section carries its kind). Within that rule, **certification coverage retains its two meanings**: the coverage *as the examiner declared it* is shown as recorded fact; any derived coverage is labelled separately as derived, and never presented in a form that could be read as another certification act.
- **O4 — waiting states by name, with their transitions (R33).** The summary renders `awaiting_gate`, `awaiting_ruling`, `holder_unavailable`, `seat_stalled`, and `paused_by_gate` by name wherever the derivations place them; no waiting state is rendered as progress; none appears or clears except as the derivations move on recorded events.
- **O5 — sealed material: existence only, including for the director (Q1, settled), by allowlist construction.** Commissioning authority does not silently grant access to sealed content; R7's boundary and R9's run-spanning view coexist. The observer shows a sealed item's existence, material reference, event position, and holding seat — never the material. The full-detail tier is not a back door, and the boundary is structural, not editorial: for an event carrying sealed material, the observer **constructs a new representation from an explicit allowlist** — only the approved existence metadata crosses: the material reference, the event position, the holding seat, the event's type and actor. The original payload is never copied across and then pruned: sensitive material under another field, a nested object, or an unexpected key has no path into the render, because nothing unlisted is carried at all. The safe representation is *incapable* of carrying the secret, rather than depending on every future renderer remembering not to display it.
- **O6 — an HTML export, static, in the carried spirit (Q3, settled).** A single self-contained page from a NEW framework template (the fabric template untouched), embedding the render via script-safe escaping applied to **every** embedded value in both tiers. The page identifies its snapshot head (sequence and hash) as what it represents; it never presents itself as the current state of a run that may have continued. Plain rendering only: the living-swarm skin is not this piece — deferred under Ben's ruling, its design to be planned with the examiner separately.
- **O7 — no write path exists; the checker stands separate (Q2, settled).** The module imports no doorway, holds no token, opens nothing writable. §3.9 closes with the observer only: the §3.10 checker remains a separate Stage 2 acceptance item, and the observer's use of the framework's own verification and derivation code — appropriate for an observer — is never represented as satisfying R4's independent-implementation requirement; technical independence and epistemic independence remain distinct, both visibly.

## Acceptance criteria (revised)

1. **Binding:** each check refuses by name, tested separately — a store with no run row; a store with duplicate run rows; a store whose **run row's ID** mismatches the requested run; a store whose **events' run IDs** mismatch (event binding tested independently of the row check — neither test stands in for the other); a store whose constitution hash mismatches; and an unreadable, missing, empty, or chain-broken store. Each refusal produces no output.
2. **Read-only, including refusal behaviour:** a render leaves the store byte-identical; the observer never instantiates FrameworkStore, never invokes the doorway, and refusing a missing store creates neither the database nor any parent directory — the filesystem is untouched by a refusal.
3. **Snapshot boundary:** the render and the page name the head (sequence + hash) they represent; statements depending on absence are qualified by that head.
4. **Provenance and kinds:** every summary statement identifies its supporting event positions; recorded and derived matter are distinguishable in the data structure and on the page; certification coverage appears both as declared (recorded) and, where presented, as derived — labelled, never merged.
5. **Waiting states:** witnesses stand for all five — `awaiting_gate`, `awaiting_ruling`, `holder_unavailable`, `seat_stalled`, `paused_by_gate` — and the recorded transitions by which each clears or changes are tested, not merely the labels.
6. **Full detail fidelity:** event order, attribution, and types are preserved intact; the summary is an explanation over the record, not a replacement for it.
7. **Sealed safety:** a fixture carrying a recognisable secret in sealed material renders with the secret **nowhere** — not in the data structure's detail tier, not in the exported HTML — while the item's existence, reference, position, and holder do appear. The fixture exercises the allowlist rule itself: a second secret placed in an **unexpected payload field** (and a third nested in an object) likewise appears nowhere, because the representation is constructed from the allowlist rather than pruned from the payload.
8. **Script safety, whole export:** a stored value containing `</script>` renders inert in both tiers.
9. **End-to-end:** a full run of the §3.8 shape (assembly → certification) renders completely, showing its operative gate set and its certification coverage as recorded.
10. **Boundaries kept:** the substrate observer and its safety suite untouched and green; all framework regressions green.
