(1) Classification enforcement (§E): on a CASE_CORRECTED the doorway recomputes the six-field diff against the case's established content (`established_case_content` / `classify_case_change`) and refuses a disagreement, an unrecorded classification, or a wrong version number, the refusal recorded as a REJECTION. - `src/framework/record.py` — `CASE_CONTENT_FIELDS` (the six); the fold's CASE_VERIFIED branch now establishes a version's verification position **and** content first-wins (§F/§D: a duplicate verification replaces neither); `version_issued` enforces the exact issuance order — correction < verification < the examiner's act < authorisation (§F) — so an examiner act recorded before the verification it answers no longer completes a route.
