# Vane — examination of the native-mode probe scope Rev 1: sound, close, NOT passed yet (2026-11-23)

Via Pulse Bridge (her letter arrived headed TO-REMMY), received 2026-11-23 ~19:05 MST. Recorded at INDEX 272. Overall judgement: the architecture is sound and the scope is close; she supports the native-mode stage as a bounded A1 addition. **Rev 1 is not passed** — a narrow Rev 2 is requested against these corrections. The most important point: **the probe must observe the model's actual interface behaviour, not accidentally observe only what the current adapter happens to be capable of accepting.**

**1. An observation boundary below response interpretation.** The capture must sit below the adapter's text-contract parsing: the raw provider response is captured **before** ordinary parsing or validation can reject, transform or discard it — otherwise a native call could be classified malformed merely because the existing adapter doesn't understand it, defeating the probe. The capture path preserves: raw response content; native tool-call names and arguments; provider refusal and error details; **provider acceptance or rejection, separately from the model's attempted behaviour**; the original response identity and integrity information. No tool results are sent back and no native conversation is continued — one generation is observed, then the trial ends.

**2. The outcome classes are not mutually exclusive — the most important correction.** One class per trial loses information: attempt 8 is simultaneously an environment-tool attempt **and** a provider refusal. Separate the evidence into **two dimensions**: *Behaviour observed* — text contract / offered native catalogue call / unoffered environment-tool attempt / mixed / malformed / refusal / **no observable model behaviour**; *Delivery status* — provider accepted / provider refused / provider failed without an attributable attempted call / response unavailable or indeterminate. Summary counts may be provided per dimension, but neither dimension is discarded; attempt 8's exact shape (environment-tool attempt × provider refused) must remain identifiable without pretending the model delivered a usable response. Offered-tool native calls and unoffered environment calls are different observations with different mode implications.

**3. Five trials stand, with a quorum.** A mode recommendation requires **at least 3 settled, classifiable trials** and a **strict majority of those settled trials**; otherwise inconclusive, and the governed assembly fails closed. (Four provider failures + one text response must not recommend text.) Provider failures remain recorded; the examiner sees the complete distribution. The suite is an assembly probe, not a statistical characterisation of a model.

**4. Raw evidence vs diagnostics.** Distinguish **probe evidence** (the complete bounded raw response, incl. native arguments and provider error body, where available), **integrity evidence** (hashes over the exact captured bytes), and **presentation** (shortened renderings). If a response exceeds the probe's defined **capture ceiling**, record that explicitly, retain the available bounded bytes, and classify the evidence as **incomplete** — never label an incomplete capture a complete raw response. The capture ceiling is explicit and independently checked.

**5. Mode selection and judgement.** The recommendation derives from the evidence by the fixed rule; the examiner's judgement records the selected mode **and its grounds**; the examiner may disagree with the recommendation but cannot silently substitute an unsupported mode; under inconclusive evidence, any decision to proceed needs a clearly stated basis and must not bypass the fail-closed rule. **The selected mode is bound into the sealed assembly object the adapter actually consumes** — the adapter must not be able to choose a mode from a prompt, an environment variable, or an unverified model name.

**6. §6 supported, two witnesses added.** (a) A native call to a granted tool and its text-form equivalent produce **equivalent doorway requests and the same governed dispatch behaviour**. (b) **Translation integrity:** a native call with altered arguments, an ungranted tool name, or a tool absent from the sealed catalogue cannot expand authority through translation — translation is a trust boundary and must preserve the original request faithfully, not quietly normalise an invalid request into an authorised one. P7 remains necessary.

**7. Ordering and freshness.** Placement right; the exact event sequence must be written against A1's existing lifecycle (probe after an allocated instance and attributable onboarding exist; before judgement, packing and activation) — predecessor and successor events named, not inferred. The configuration fingerprint includes **all** inputs that can change observed interface behaviour: provider route; pinned model identifier; probe suite version and hash; offered native tool definitions; **relevant request parameters and tool-choice configuration**. Any change invalidates the probe for mode selection; no inheritance across assemblies.

**Verdict: Rev 1 not passed; a narrow Rev 2 incorporating these corrections is recommended.** The five-trial proposal stands subject to the quorum; the synthetic tools and non-execution boundary are sound; the native-to-doorway translation design is sound. **The central correction: preserve the difference between what the model attempted, what the provider accepted, and what the framework actually executed — three different facts the probe must never collapse into one.** A further thought, recorded: the proposal establishes a repeatable way for the framework to learn how a newly assembled model communicates before it is allowed to do real work — valuable for Ben's model-swapping architecture. **No implementation or worker attempt is authorised by this examination.**
