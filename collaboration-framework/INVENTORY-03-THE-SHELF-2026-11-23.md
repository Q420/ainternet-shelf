## System 5 — The shelf (GitHub repo `Q420/ainternet-shelf` + local staging tree)

- **Purpose.** The shared, durable memory of the whole programme: designs, rulings, examinations, evidence bundles, build records and project folders, kept where any participant — Ben, Remmy, a seat, a future blind agent — can retrieve the same text and cite the same state. It is the one system in the specimen that was *designed* as shared brain rather than growing into the role. [demonstrated]
- **Components.** (a) The GitHub repository itself (git: content-addressed blobs, commit history, branches). (b) The local staging tree `~/workspace/ainternet-shelf/` — **not a clone**: a working mirror Remmy copies files into before pushing; it can drift from the repo if a push fails or is skipped. (c) The push route: the GitHub connector's `push-files` (whole-file snapshots, text only, an approval card per push). (d) The read route: the connector's `get_file_contents`, returning text plus the blob SHA. (e) Hand-maintained structure: top-level areas by programme (`duenna/` 2,926 files, `loom/` 3,637, `bridge/` 274, `collaboration-framework/` 224, `record/` 84, plus smaller areas) and per-folder INDEX files. Staging tree at inventory time: 8,665 files, 184 MB [observed, this session]. (f) Hygiene evidence, recorded as found: roughly fifty `paths-*.nul` scratch files from past pushes sit at the staging root — working residue inside the brain's mirror.
- **Inputs.** Files authored locally (by Remmy, or received from seats via the bridge and filed by Remmy), copied to staging, pushed in named commits. One seat is an exception: Claude files his own deliverables on shelf branches; merging to main is Remmy's hand [from the programme record].
- **Outputs.** File text + blob SHA on read; commit SHAs pinning whole states; diffs between commits (the examiner's working surface). A read returns the **whole file** — there is no fragment or query retrieval.
- **State.** Git history is the state: every pushed state is recoverable, and a commit names an exact configuration of the whole tree. Files are edited by replacement (new blob, new commit); nothing is silently mutated. The staging tree is a second, weaker state — current only when the last push is verified landed.
- **Context.** The shelf is how context crosses agents and sessions in practice: seat letters carry shelf paths instead of bodies (Ben's 2,000-character bridge cap made this a rule), and a seat works from the shelved text. But retrieval is **self-directed**: the reader chooses what to open, whole file at a time, at full context cost. There is no distilled view, no per-assignment retrieval manifest, and no record of what a reader actually read — a seat's reading is evidenced only when it cites commits/blobs in its reply (Vane's discipline, practised by hand).
- **Authority.** **The shelf carries no authority, and that is by design accident rather than by mechanism.** A shelved file is evidence or design, never permission: Ben's approvals live elsewhere — the scope ledger and gate ledger are **local-only files, not shelved** [observed, this session] — and Ben's taps happen in chat. Conversely, nothing on the shelf is access-partitioned: open designs and sealed examination material are separated by folder convention only; anyone with repo access reads everything. "Shared brain does not mean shared authority" (Vane) currently holds because authority lives off-shelf, not because the shelf enforces anything.
- **Capabilities.** [demonstrated] Pin a state and cite it exactly (the classification dispute of 2026-11-23 died in one round because both parties could re-open the same blob); survive any agent, session or machine (the repo is the continuity of the programme across every seat change since October); serve a blind reader (a new seat with repo access and a path can reconstruct the work's state — the briefcase's shared-brain assumption, working today); preserve disagreement (examinations, concessions and NO-START verdicts are shelved beside the work they judge).
- **Interfaces.** Connector read/write calls for Remmy; GitHub web for Ben; the seats' own GitHub access for reading at commits. No API is offered to framework code — the Stage 2 build does not read the shelf; its record is its own store, and shelving the framework folder is a Remmy-side publishing act after the fact.
- **Lifecycle.** Author → stage → push (approval card) → verify one blob by read-back → cite by commit. Branches exist (Claude's deliverables) but main is the working truth; the framework folder rule (INDEX updated in the same round as any change) is a lifecycle discipline imposed by Ben because the shelf itself imposes none.
- **Evidence.** The strongest evidence system in the specimen: blob SHAs make "the same text" a checkable claim, commits make "the state at the time" recoverable, and the push-verification discipline (read-back after every push; PUSH PENDING recorded when a push doesn't land) exists because unverified sends failed before. [demonstrated repeatedly; most recently the Inventory 01 blob check that settled the classification dispute.]
- **Ownership.** Ben's GitHub account and repo; Remmy operates it under his authorisation; seats read under theirs.
- **Dependencies.** GitHub availability; the connector's OAuth health; Ben's approval taps for pushes; Remmy's staging discipline.
- **Constraints.** [demonstrated] The push route is **text-only** — the live-demo run database could not be shelved and travelled as base64 + a JSON export instead. A single push of a large tree fails (HTTP 413) — pushes are split into batches. Whole-file reads only. No search layer: findability is folder structure + hand-kept INDEX files, nothing else.
- **Failure modes.** [demonstrated] (1) **Stale retrieval at the reader's end** — a seat's tooling has repeatedly served old text for a shelved file; the defence is commit-pinning and blob citation, practised as discipline, not enforced by the shelf. (2) **Staging drift** — a failed or forgotten push leaves the mirror ahead of the brain; the verify-by-read-back rule is the counter. (3) **Index rot** — on 2026-11-22 the framework INDEX pointed at unnumbered design files whose identity hadn't been verified; Ben's "make sure first" and a diff settled it. The brain's map is hand-drawn; where the map is wrong, the brain is effectively missing those files. (4) **Residue accumulation** — scratch files at the staging root (above) show the mirror collects working debris the repo then inherits if pushed carelessly.
- **Cost.** Pushes cost an approval tap each; reads cost full-file context; the INDEX discipline costs Remmy attention every round — the folder rule exists because skipping it proved more expensive.
- **Maturity.** Implemented and load-bearing: the programme's memory of record for two months; the framework's canonical folder lives here.
- **Briefcase test.** **The closest pass in the specimen — and still a pass on storage, not on provision.** The shelf is exactly the shared brain the briefcase design assumes: durable, versioned, citable, readable by a blind agent, indifferent to which agent wrote it. What it does not do is *provision*: it cannot hand a worker the right subset, cannot show what a worker retrieved, cannot keep sealed material from a reader whose case excludes it, and cannot receive a worker's output under the worker's own case attribution (writes are Remmy's publishing acts, or one seat's branch habit). The briefcase names what must be retrieved; the shelf, today, trusts the reader to retrieve it. That trust is the gap — the same provision gap as skills (Inventory 01), one level down.

## Preliminary gap observations (continuing the numbering — observations, not the gap map)

- **G10 — No retrieval contract.** A worker's reading leaves no trace unless the worker cites blobs by discipline. The framework needs the case to name required retrievals and the record to show them — Vane's commit-citing practice is the manual prototype of a read-receipt discipline.
- **G11 — No access partitioning.** Open and sealed material differ by folder convention, not enforcement. A generated worker whose case excludes sealed ground truth currently has no shelf-side boundary; the doorway would have to mediate every read, or the shelf needs partitioned areas with real access control.
- **G12 — The write path is person-centric.** Shelving is Remmy's act (plus Claude's branch habit), not an office operation attributed to a case. In the framework, a worker's deliverable should land in the shared brain *as that worker's recorded act under its case*, with the office's verification — today that chain is Remmy's hands and habits.
- **G13 — Findability is diligence, not structure.** Folder INDEX files work because they are maintained under Ben's same-round rule. A generated worker cannot rely on a human's filing habits; the gap map should ask what machine-findable structure (manifests, typed links, per-case indexes) the brain needs.
